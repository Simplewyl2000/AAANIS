# AXIS 第一阶段：运行时能力发现

你是由确定性脚本调度的本地 Codex 调查子任务。你不决定任务范围，只调查
`batch.json` 中分配给你的全部项目。

## 目标

把候选名称继续展开成可执行能力。对每个项目找到：

1. 它属于什么运行时对象或操作；
2. 它的属性、方法、输入参数和返回值；
3. 参数是普通值、对象引用、集合、文件、图层还是区域；
4. 它需要什么父对象、子对象和前置上下文；
5. 怎样创建最小测试对象并执行；
6. 执行后有什么可观察结果；
7. 保存并重新打开后变化是否仍然存在。

## 必须使用的输入

- 分配清单：`{{BATCH_PATH}}`
- AXIS 根目录（只读参考）：`{{AXIS_ROOT}}`
- 当前软件已有普查：`{{CENSUS_PATH}}`
- 当前软件已有账本：`{{LEDGER_PATH}}`
- 六软件递归试验标杆：`{{GOOD_PRACTICE_PATH}}`
- 本批运行时类型：`{{RUNTIME_FAMILY}}`

先读取分配清单和现有账本。已有结果能够直接证明的部分应复用，不要重新设计
AXIS，也不要重写已经存在的普查器。

不要把完整的大型 `report.json`、日志或全部命令说明读入上下文。先从当前
`symbol` 和已有命令名出发，用 `rg` 或 `jq` 只提取对应记录。

## 调查规则

### 所有软件共同规则

- 从真实运行时对象出发，不根据模型记忆猜接口。
- 读取对象的直接属性后，继续追踪对象引用、集合、方法返回对象和子对象。
- 读取完整方法参数：名称、类型、可选性、默认值、枚举范围和返回类型。
- 每个参数必须填写机器可读的 `value_kind`。对象引用要填写运行时
  `target_type`，不能因为 CLI 输入来自字符串就把它登记成普通字符串。
- 参数没有默认值时把 `default` 写成空字符串；有默认值时写成可读字符串。
  没有枚举范围时把 `values` 写成空数组。
- 对带参数的 getter，根据类型机械生成最小合法参数，再进入返回对象。
- 一个调用失败时，先判断是否缺少对象、选区、模式、文件类型或父容器。
- 每个项目最多进行 `{{MAX_ATTEMPTS}}` 组有区别的上下文尝试，并全部记录。
- 只改变窗口、选择或临时状态的项目可以判为 `out_of_scope`，但必须有运行时证据。
- 如果已有命令完整覆盖相同文件效果，可以判为 `equivalent`，并写出对应命令。
- 只有在多个合法上下文中完成真实调用，并证明当前软件运行时无法形成该文件
  效果时，才能判为 `unsupported`。这是一项有证据的最终结论。
- 无法取得充分证据时必须返回 `blocked`，不允许写成不支持后跳过。
- 一个账本项目可能对应多条命令。例如一个对象可能同时需要创建、删除、读取和
  修改命令。必须把所有可执行操作写入 `command_candidates`，不能只挑一条代表
  命令。已有命令也要列入后再补齐缺失部分。
- 每条 `command_candidates` 必须选择一种 `implementation_route`：
  普通属性直接赋值；枚举先校验；对象引用先按名称或稳定标识解析成真实对象；
  结构体和有类型的集合先构造运行时值；对象创建必须走软件工厂；依赖选择、活动
  对象或编辑模式的多步动作必须在一次软件会话内完成。
- 每条候选命令都要填写 `persistence_check`，明确命令执行、保存、关闭、重开后
  用什么独立读取方式确认文件效果。没有这个检查的候选不能标为可执行。

### UNO（Writer、Calc、Impress）

- 使用对象的 `getTypes()`、`getPropertySetInfo()` 和 UNO 类型描述管理器。
- 递归读取接口的基接口，否则会漏掉 `setString` 等继承方法。
- 对 `XCell`、`XTable`、`XIndexAccess`、`XNameAccess` 等返回对象继续展开。
- 普通 JSON 值不能代替 UNO 对象引用或结构体。

### Blender RNA

- 不得跳过 `POINTER` 和 `COLLECTION`。
- 记录 `fixed_type`，并用名称解析为真实 `bpy.data` 对象后进行绑定测试。
- 算子除了参数签名，还必须记录需要的对象模式、活动对象和选择状态。

### QGIS

- 不能只记录 Qt 方法数量；记录实际方法名和可取得的签名。
- 从 `QgsProject`、图层、渲染器、标注和布局对象继续追踪返回对象。
- 项目编辑能力必须保存 `.qgs/.qgz` 并重新打开验证。

### GIMP

- 从 PDB 读取过程参数和返回值，并追踪 image、drawable、layer、channel 等 ID
  之间的关系。
- 多步操作要验证选区、图层和通道状态是否跨调用保留。

## 证据要求

把探针脚本、输入文件、输出文件和日志放在当前批次目录下的 `evidence/`。
最终 JSON 中的每条证据路径必须是相对于当前批次目录的路径，并且文件真实存在。

以下状态需要的最低证据：

- `executable`：运行时签名 + 成功调用日志 + 外部观察结果；
- `equivalent`：现有命令说明 + 两条路径产生相同效果的比较结果；
- `out_of_scope`：运行时证明它只改变临时界面状态，或者不能进入持久文件；
- `unsupported`：接口签名、多个合法上下文的调用日志和具体运行时限制；
- `blocked`：所有尝试及具体阻塞条件。

## 输出纪律

- `batch.json` 中每个 `item_id` 必须在最终结果中出现一次且仅一次。
- `command_candidates` 是完整候选清单，不是示例清单；名称按 AXIS 已有
  `kebab-case` 规则给出，并注明能力类别、目标定位方式和参数。
- 不得返回额外项目。
- 不得修改正式 census、ledger、atlas、commands 或 dist。
- 最终消息只输出符合指定 JSON Schema 的 JSON，不添加解释性前后缀。
